# TRACKROOM v5.4 — 다국어 앨범 커버 매칭 · 재검색

기존 **Last.fm 검색, 로그인, 추천방, 무한 버블 캔버스**를 그대로 유지하면서 앨범 커버 연결을 개선했습니다.

## 무엇이 바뀌나요?

- **후한 매칭:** 곡 제목에서 대소문자·띄어쓰기·괄호 속 피처링·리마스터 표기를 정리하고, **긴 제목에 한정해 작은 오탈자**를 허용합니다. 아티스트까지 일치해야 커버를 연결합니다. `Live`, `Remix`, `Acoustic` 등은 다른 버전으로 취급합니다.
- **영문·한글 이름 비교:** Last.fm URL의 원래 표기, 주요 아티스트의 한영 예명, 그리고 **MusicBrainz에 등록된 실제 별칭·번역 제목**을 추가로 확인합니다. **모든 곡을 자동 번역하는 기능은 아닙니다.** 정식 음악 데이터베이스에 대체 표기가 없는 곡은 여전히 매칭되지 않을 수 있습니다.
- **단계적 재검색:** iTunes US/JP 카탈로그에서 넓게 찾은 후, 찾지 못한 음악은 **곡+가수별 추가 검색**을 진행합니다. 곡 등록·커버 복구 단계에서만 MusicBrainz 별칭 검색을 추가해 일반 검색 속도를 지킵니다.
- **기존 음원 다시 검색:** 버블 화면의 **앨범 커버 복구(▧)** 버튼을 누르면 **이전 실패 여부에 상관없이** 커버가 없는 곡을 4곡씩 다시 검색합니다. 결과가 없는 곡도 재검색 대상으로 순환합니다. 복구 시 닉네임·추천 이유·좋아요·재생 구간은 유지됩니다.
- **추가 결제·API 키 없음:** 기존 `LASTFM_API_KEY`를 그대로 사용합니다. MusicBrainz는 공식 공개 검색 API로 조회합니다.

## GitHub 배포

`update-only.zip` 파일을 풀어서 저장소의 다음 파일 **두 개만** 교체하세요.

```text
server.py
public/app.js
```

GitHub 커밋 → Render 자동 배포(`Live`) → 브라우저 강력 새로고침(`Ctrl+Shift+R`).

## 제한 및 참고

- Apple/iTunes Store에 없는 곡, 다른 언어로만 발매되어 서로 연결되는 별칭 정보가 없는 곡은 커버가 없을 수 있습니다.
- 매우 비슷한 제목이지만 **다른 아티스트/라이브/리믹스 버전**인 결과는 자동 적용하지 않습니다.
- 외부 API 실패나 지연이 있으면 검색/재검색 결과에서 커버가 생략될 수 있습니다.
- 기존 Render 무료 인스턴스의 로컬 SQLite는 **배포 시 데이터가 초기화될 수 있습니다**. 추천곡이 중요하면 영구 데이터베이스 설정을 먼저 확인하세요.
- 이미지 사용은 Apple 등의 카탈로그 사용 조건을 따라야 합니다. 사이트 URL이 외부에서 접근 가능하다면 '친구끼리 테스트'여도 완전한 비공개 서비스는 아닙니다.

### 테스트

`python -m unittest discover -s tests -v`

모든 서버 API 관련 테스트는 네트워크 응답을 모의한 로컬 테스트이며 실제 Render 연결과 Apple/MusicBrainz 라이브 카탈로그 결과까지 보장하지 않습니다.
