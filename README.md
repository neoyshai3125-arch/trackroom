# TRACKROOM v5 — 무한 버블 캔버스 UI

TRACKROOM의 기존 음악 추천방을 **원형 앨범 커버 기반 버블 탐색 화면**으로 바꾼 버전입니다. 기본은 v4 Last.fm 통합 검색 기능이며, 이미 사용 중인 **Apple/iTunes 공개 카탈로그 검색 옵션**도 함께 노출해 기존에 보이던 앨범 커버를 버블에서 활용할 수 있게 했습니다.

## 사용 방법

- 추천방에 들어가면 추천곡들이 **원형 버블**로 보입니다.
- PC: **마우스로 드래그**해 탐색, **휠로 확대·축소**, 버블 클릭 시 상세 정보 표시.
- 모바일: **한 손가락으로 이동**, **두 손가락으로 확대·축소**, 버블 터치 시 상세 정보 표시.
- 화면 하단 버튼: `+` 확대 / `−` 축소 / `⌖` 중앙 복귀 / `↝` 다른 추천곡으로 이동.
- **음악 추가**를 누르면 기존 검색과 등록 기능이 오른쪽 패널(모바일은 아래쪽 패널)로 열립니다.
- 버블 상세 화면에서 추천 이유, 구간, 원본 링크, 좋아요, 내 곡 삭제가 가능합니다.
- 곡이 적을 때는 그 곡들만 표시되고, 곡이 많아지면 이동할 수 있는 공간이 넓어집니다. 서버에 없는 음원을 무한 생성하거나 기존 곡을 무한 반복하지 않습니다.

## 앨범 커버 이미지

- **이미 저장된 `artworkUrl`이 있는 곡**은 그 URL의 이미지를 별도 다운로드·캡처 없이 CSS로 원형 표시합니다. 예: 기존 Apple/iTunes 검색으로 등록한 곡.
- **Last.fm 결과는 버전 4 정책을 유지**하여 별도 앨범 이미지 URL을 수집하지 않습니다. 이 곡들은 추상 그래픽과 음악 아이콘으로 표시됩니다.
- 브라우저가 이미지 URL을 불러오지 못하면 자동으로 기본 아이콘을 표시합니다.
- 버블에 사용된 이미지의 출처/이용 약관은 별도 검토가 필요합니다. **원형으로 자르거나 서버 저장을 생략해도 저작권 사용 허락이 자동으로 생기지는 않습니다.**

## GitHub 업로드 및 Render 배포

권장: **`trackroom-bubble-v5-update-only.zip`** 안의 변경 파일을 기존 GitHub 저장소의 동일 경로에 적용하세요. 이전에 Apple/iTunes만 쓰던 v3.1에서 업데이트하는 경우에도 적용되도록 `server.py`를 함께 포함했습니다.

```
server.py     ← v4 Last.fm / Apple 검색 백엔드
public/
  index.html   ← 변경
  app.js       ← 변경
  style.css    ← 변경
```

- `server.py`는 v4 기반 검색 백엔드이며 v3.1에서 설치할 때 함께 업데이트합니다. 기존 v4와 내용이 같지만, 함께 올려도 무방합니다.
- 기존 `requirements.txt`, DB 파일은 수정하거나 GitHub에 업로드할 필요가 없습니다. 현재 코드는 `v4` 서버를 기준으로 테스트했습니다.
- GitHub 반영 후 Render에서 새 버전 배포가 완료되면 웹브라우저를 새로고침(`Ctrl+Shift+R`)하세요.
- Render 무료 플랜의 로컬 DB는 재배포/재시작에 따라 없어질 수 있습니다. **중요한 데이터가 있으면 먼저 백업하고 영구 저장소를 붙인 후 배포하세요.**
- 로그인·방 생성·검색·음원 등록 등 서버 기능과 무관한 업데이트이므로 기존 방 데이터 구조를 바꾸지 않습니다.

## 비공개 운영 주의

`onrender.com`으로 배포된 사이트는 일반적으로 URL을 아는 사람이 접근할 수 있습니다. 방 초대 코드와 로그인은 **사이트 자체를 비공개로 만들지는 않습니다.** 테스트 전 공개 접근/권한과 음악 메타데이터 API 및 앨범 이미지 라이선스 조건을 별도로 확인하세요.

## 개발 / 테스트

- Python 3.9+ 환경: `python server.py`
- 기존 서버 단위 테스트: `python -m unittest discover -s tests -v`
- 실제 Last.fm 검색에는 Render/로컬 환경변수 `LASTFM_API_KEY`가 필요합니다.
- 외부 이미지 다운로드나 오디오 재생 코드는 추가하지 않았습니다.
