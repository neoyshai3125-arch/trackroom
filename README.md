# TRACKROOM v5.5 — Apple/iTunes 기본 검색 · 앨범 검색 · 버블 정렬

기존 TRACKROOM의 로그인, 프로필, 추천방, 무한 버블 캔버스, Last.fm 검색을 유지하면서 아래 기능을 추가한 업데이트입니다.

## 새 기능

1. **Apple/iTunes 기본 검색:** 음악 추가 창을 열면 Apple/iTunes 공개 카탈로그가 기본 선택됩니다. Last.fm은 보조 검색으로 남습니다.
2. **검색 기준:** 곡 제목 / 아티스트 / 앨범명 중 선택할 수 있습니다. 앨범명으로 검색하면 앨범 → 수록곡 → 개별 음원 선택 → 추천방 등록 순서로 진행합니다.
3. **버블 배치 최신순·인기순:** 최신순은 등록 시각 순, 인기순은 좋아요 수 내림차순(동점일 때 최신순)입니다. 높은 우선순위의 곡이 **버블 캔버스 중앙**으로 옵니다. 화면은 계속 버블형이며 목록 UI로 바뀌지 않습니다.
4. **Last.fm 이미지 누락 보완:** Last.fm 음원 검색 결과의 커버가 없는 곡은 제목과 아티스트만으로 Apple/iTunes 커버를 확인합니다. 검색 결과를 먼저 보여주고 커버는 순차적으로 조회하여 채웁니다. 기존 버블의 커버 복구 버튼도 유지됩니다.

## 주의 사항

- **Apple/iTunes 공개 API**는 한국 **Apple Music 전체 스트리밍 카탈로그와 다릅니다.** 공개 iTunes Store 음악 검색은 미국·일본 카탈로그를 순차 조회하며 일부 한국 음원이 검색되지 않을 수 있습니다.
- Apple Music 개발자 토큰을 별도로 설치한 환경에서는 기존의 Apple Music 곡 검색이 사용될 수 있습니다. 앨범 검색과 수록곡 목록은 공개 iTunes Store 카탈로그 기준입니다.
- 실제 음원을 재생/다운로드하지 않습니다. 카탈로그 검색으로 확인한 곡만 등록합니다.
- 앨범 선택 자체는 등록되지 않으며, 앨범의 수록곡 중 하나를 선택해야 등록할 수 있습니다.
- API 이미지 이용 조건, 서버의 개인정보 보호 및 회원정보 보존은 별도 검토가 필요합니다.
- Render 무료 인스턴스의 로컬 SQLite 데이터는 재배포/재시작 시 지워질 수 있습니다. **기존 회원·추천곡을 보존해야 한다면 먼저 DB를 영구 저장소로 옮기거나 백업해 주세요.**
- Apple/iTunes 검색 API 호출은 공식적으로 분당 약 20회 정도로 제한됩니다. Last.fm 커버 보완에는 요청 제한을 적용했습니다. 운영 환경에서 캐싱/호출량 제한을 추가로 고려하세요.

## 기존 사이트에 적용

ZIP 압축을 해제한 다음, 아래 네 파일을 GitHub 저장소의 **같은 위치**에 교체하고 Commit하세요.

```
server.py
public/index.html
public/app.js
public/style.css
```

Render의 Start Command는 기존과 동일한 `python server.py`를 유지합니다. Apple/iTunes 공개 검색에는 API 키가 따로 필요하지 않습니다. Last.fm을 보조 검색으로 계속 이용하려면 기존 `LASTFM_API_KEY` 설정을 유지하면 됩니다.

GitHub 파일이 교체되고 Render 배포가 완료된 후 브라우저에서 강력 새로고침(`Ctrl + Shift + R`)을 하세요.
